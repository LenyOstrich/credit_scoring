# Генерация и проверка признаков

Документ описывает подготовку окружения, генерацию признаков для датасетов Home Credit Default Risk и проверку полученных результатов.

Поддерживаются два варианта генерации:

- **Совместный запуск** — расчёт признаков для всех файлов одним скриптом.
- **Раздельный запуск** — расчёт признаков только для выбранного источника данных.

## 1. Подготовка окружения

Клонируйте репозиторий и перейдите в его корневой каталог:

```powershell
cd путь\к\credit_scoring
```

Активируйте виртуальное окружение проекта:

```powershell
.venv\Scripts\activate
```

Если виртуальное окружение ещё не создано, создайте его и установите зависимости проекта в соответствии с инструкциями в `pyproject.toml`.

Перед запуском убедитесь, что исходный датасет Home Credit Default Risk доступен. При необходимости скрипт предложит загрузить его с Kaggle.

## 2. Генерация признаков

### 2.1. Совместная генерация всех признаков

Рекомендуемый способ — запуск общего скрипта, который последовательно рассчитывает признаки для всех поддерживаемых источников данных.

Из корневого каталога проекта выполните:

```powershell
python -m app.modelling.features.run_all_features
```

Скрипт последовательно:

1. Проверяет доступность исходных данных и при необходимости предлагает их загрузить.
2. Запрашивает подтверждение запуска генерации признаков.
3. Подготавливает каталог для сохранения результатов.
4. Рассчитывает признаки
5. Выводит сообщение об успешном завершении генерации всех признаков.

В зависимости от состояния исходных данных и настроек скрипт может запросить подтверждение загрузки, путь к данным и разрешение на расчёт.

При запросе каталога для сохранения результатов укажите путь либо нажмите Enter, чтобы использовать предложенный путь по умолчанию.

Рекомендуемый каталог для результатов — `data/processed`.

### 2.2. Раздельная генерация признаков application

Для расчёта признаков из файлов `application_train.csv` и `application_test.csv` выполните:

```powershell
python -m app.modelling.features.application_train_test_features
```

Скрипт подготовит исходные данные, запросит подтверждение запуска и рассчитает признаки для обучающей и тестовой выборок.

Результаты сохраняются в файлы:

- `application_train.csv`
- `application_test.csv`

### 2.3. Раздельная генерация признаков bureau

Для расчёта признаков из файла `bureau.csv` выполните:

```powershell
python -m app.modelling.features.bureau_features
```

Скрипт использует сведения о кредитной истории клиентов и рассчитывает агрегированные признаки по каждому клиенту.

Результат сохраняется в файл:

- `bureau_features.csv`

В итоговой таблице используется идентификатор клиента `SK_ID_CURR`. Он позволяет объединить полученные признаки с другими наборами признаков клиента.

### 2.4. Раздельная генерация признаков bureau_balance

Для расчёта признаков на основе файлов `bureau_balance.csv` и `bureau.csv` выполните:

```powershell
python -m app.modelling.features.bureau_balance_features
```

Скрипт использует историю ежемесячных статусов кредитов из `bureau_balance.csv` и информацию о кредитах из `bureau.csv`.

Поскольку `bureau_balance.csv` содержит идентификаторы кредитов `SK_ID_BUREAU`, для получения признаков на уровне клиента выполняется связь с `bureau.csv` по этому идентификатору.

Скрипт рассчитывает следующие группы признаков:

- количество всех кредитов клиента;
- количество открытых и закрытых кредитов;
- количество кредитов, в истории которых встречалась просрочка;
- количество кредитов с различными диапазонами просрочки;
- доли открытых, закрытых и просроченных кредитов;
- доли кредитов с различными диапазонами просрочки;
- количество дней с момента последнего закрытия кредита;
- количество дней с момента оформления последнего активного кредита относительно текущей заявки.

Для определения открытых и закрытых кредитов используется столбец `CREDIT_ACTIVE` из `bureau.csv`. Для определения истории просрочек используется столбец `STATUS` из `bureau_balance.csv`.

Кредит считается просроченным, если в его истории встречался хотя бы один из статусов `1`, `2`, `3`, `4` или `5`.

Результат сохраняется в файл:

- `bureau_balance_features.csv`

Индексом итоговой таблицы является `SK_ID_CURR`, что позволяет объединить признаки с другими наборами признаков клиента.

## 3. Проверка признаков application

После успешного завершения генерации выполните:

```powershell
python scripts/check_application_features.py
```

Укажите каталог с обработанными датасетами либо нажмите Enter, чтобы использовать предложенный путь по умолчанию.

Скрипт проверяет наличие файлов `application_train.csv` и `application_test.csv`, а также выводит размер каждого датасета, количество пропусков и количество уникальных значений для каждого проверяемого признака.

Проверяются следующие 13 признаков:

- `docs_number`
- `has_full_apprt_info`
- `age_in_years`
- `years_since_doc_change`
- `doc_change_age`
- `has_doc_change_delay`
- `loan_income_ratio`
- `children_per_adult`
- `income_per_child`
- `income_per_adult`
- `ext_source_score`
- `income_group_diff`
- `interest_rate`

Если признак отсутствует, скрипт выводит сообщение об ошибке.

## 4. Проверка признаков bureau

После успешного завершения генерации выполните:

```powershell
python scripts/check_bureau_features.py
```

Укажите каталог с обработанными датасетами либо нажмите Enter, чтобы использовать предложенный путь по умолчанию.

Скрипт проверяет наличие файла `bureau_features.csv`, наличие обязательных признаков, уникальность идентификаторов клиентов, количество пропусков и количество уникальных значений признаков.

### 4.1. Обязательные признаки

Проверяются следующие признаки:

- `max_overdue_amount` — максимальная сумма просрочки по кредитам клиента.
- `min_overdue_amount` — минимальная сумма просрочки по кредитам клиента.
- `overdue_to_open_credit_ratio` — отношение суммы максимальных просрочек по кредитам клиента к общей сумме его активных кредитов.

### 4.2. Признаки по типам кредитов

Дополнительно проверяются признаки, названия которых формируются динамически на основе категорий `CREDIT_TYPE` в исходном датасете:

- `credit_count_<тип кредита>` — количество кредитов определённого типа.
- `overdue_credit_count_<тип кредита>` — количество кредитов определённого типа с положительной суммой максимальной просрочки.
- `closed_credit_count_<тип кредита>` — количество закрытых кредитов определённого типа.

Количество таких признаков зависит от типов кредитов, присутствующих в исходных данных.

### 5. Проверка признаков bureau_balance

После успешного завершения генерации выполните:

```powershell
python scripts/check_bureau_balance_features.py
```

Укажите каталог с обработанными датасетами либо нажмите Enter, чтобы использовать предложенный путь по умолчанию.

Скрипт проверяет наличие файла `bureau_balance_features.csv`, наличие обязательных признаков, уникальность идентификаторов клиентов, количество пропусков и количество уникальных значений признаков.

Дополнительно проверяется отсутствие отрицательных значений в количественных признаках и соответствие долей диапазону от 0 до 1.

#### 5.1. Количественные признаки

Проверяются следующие признаки:

- `credit_count` — общее количество кредитов клиента.
- `open_credit_count` — количество открытых кредитов.
- `closed_credit_count` — количество закрытых кредитов.
- `overdue_credit_count` — количество кредитов, в истории которых встречалась просрочка.
- `overdue_status_1_credit_count` — количество кредитов, в истории которых встречался статус `1`.
- `overdue_status_2_credit_count` — количество кредитов, в истории которых встречался статус `2`.
- `overdue_status_3_credit_count` — количество кредитов, в истории которых встречался статус `3`.
- `overdue_status_4_credit_count` — количество кредитов, в истории которых встречался статус `4`.
- `overdue_status_5_credit_count` — количество кредитов, в истории которых встречался статус `5`.

#### 5.2. Признаки-доли

Проверяются следующие признаки:

- `closed_credit_ratio` — доля закрытых кредитов от общего количества кредитов.
- `open_credit_ratio` — доля открытых кредитов от общего количества кредитов.
- `overdue_credit_ratio` — доля кредитов, в истории которых встречалась просрочка.
- `overdue_status_1_credit_ratio` — доля кредитов со статусом `1` в истории.
- `overdue_status_2_credit_ratio` — доля кредитов со статусом `2` в истории.
- `overdue_status_3_credit_ratio` — доля кредитов со статусом `3` в истории.
- `overdue_status_4_credit_ratio` — доля кредитов со статусом `4` в истории.
- `overdue_status_5_credit_ratio` — доля кредитов со статусом `5` в истории.

Доли рассчитываются относительно общего количества кредитов клиента. Один кредит может учитываться в нескольких диапазонах просрочки, если его статус менялся в разные месяцы. Поэтому сумма долей по отдельным диапазонам не обязана равняться общей доле просроченных кредитов.

#### 5.3. Временные признаки

Проверяются следующие признаки:

- `days_since_last_closed_credit` — количество дней между фактическим завершением последнего закрытого кредита и текущей заявкой.
- `days_since_last_active_credit_application` — количество дней между оформлением последнего активного кредита и текущей заявкой.

Если необходимая дата отсутствует в исходных данных, соответствующий признак может содержать пропуск. Такие пропуски не обязательно свидетельствуют об ошибке генерации.

### 6. Ожидаемые результаты

После успешной совместной генерации в каталоге результатов должны находиться следующие файлы:

```text
data/
└── processed/
    ├── application_train.csv
    ├── application_test.csv
    ├── bureau_features.csv
    └── bureau_balance_features.csv
```

Фактический путь может отличаться, если при запуске был указан другой каталог.

После запуска проверяющих скриптов в логе должна отображаться статистика по проверяемым признакам и сообщение о завершении проверки.
